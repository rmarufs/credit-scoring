# Credit Scoring

Сервис кредитного скоринга для оценки вероятности дефолта заёмщика по анкетным и кредитным параметрам заявки. В состав проекта входят пайплайн очистки данных и обучения модели градиентного бустинга (`CatBoost`), сохранённые артефакты модели и метаданных, HTTP-сервис на базе `FastAPI` и конфигурация контейнеризации `Docker`.

## Быстрый старт

Обученная модель (`models/model.pkl`) и метаданные (`models/metadata.json`) включены в репозиторий. Сырой датасет для запуска API не требуется.

1. Клонировать репозиторий и перейти в каталог проекта:

```bash
git clone <URL_РЕПОЗИТОРИЯ>
cd credit-scoring
```

2. Собрать образ и запустить контейнер:

```bash
docker compose up --build
```

Для запуска в фоновом режиме используется флаг `-d` (`docker compose up --build -d`). Интерактивная документация Swagger UI доступна по адресу `http://localhost:8000/docs`.

3. Пример запроса `POST /predict` с валидной заявкой:

```bash
curl -X POST http://localhost:8000/predict \
  -H "Content-Type: application/json" \
  -d '{
    "person_age": 28,
    "person_income": 65000,
    "person_home_ownership": "MORTGAGE",
    "person_emp_length": 5.0,
    "loan_intent": "EDUCATION",
    "loan_grade": "B",
    "loan_amnt": 8000,
    "cb_person_default_on_file": "N",
    "cb_person_cred_hist_length": 6
  }'
```

Пример ответа (`200 OK`):

```json
{
  "probability_of_default": 0.028228600383371338,
  "decision": "approve",
  "threshold": 0.16
}
```

4. Остановить и удалить контейнер:

```bash
docker compose down
```

## API

### Эндпоинты

| Метод | Путь | Описание |
|---|---|---|
| `GET` | `/health` | Проверка работоспособности сервиса, статуса загрузки модели, текущего порога и версии `CatBoost` |
| `POST` | `/predict` | Расчёт вероятности дефолта по параметрам заявки и принятие решения (`approve` / `decline`) |

Пример ответа `GET /health` (`200 OK`):

```json
{
  "status": "ok",
  "model_loaded": true,
  "threshold": 0.16,
  "catboost_version": "1.2.10"
}
```

### Входные поля `POST /predict`

Входная схема содержит 9 полей (`extra="forbid"` — неизвестные поля отклоняются). Признак `loan_int_rate` исключён из модели и на вход не подаётся. Производный признак `loan_percent_income` во входном запросе не передаётся: сервис вычисляет его самостоятельно как `loan_amnt / person_income` через общую функцию `src.features.prepare_features`.

| Поле | Тип | Обязательное | Допустимые значения / диапазон | Описание |
|---|---|---|---|---|
| `person_age` | `int` | да | `20..80` | Возраст заёмщика, лет |
| `person_income` | `float` | да | `> 0`, `<= 1 000 000` | Годовой доход заёмщика |
| `person_home_ownership` | `str` (`Literal`) | да | `"RENT"`, `"OWN"`, `"MORTGAGE"`, `"OTHER"` | Статус владения жильём |
| `person_emp_length` | `float \| null` | нет (`default: null`) | `0..40` или `null`; не более `person_age - 14` | Стаж работы в годах (пропуск допустим и передаётся в `CatBoost` как `NaN`) |
| `loan_intent` | `str` (`Literal`) | да | `"DEBTCONSOLIDATION"`, `"EDUCATION"`, `"HOMEIMPROVEMENT"`, `"MEDICAL"`, `"PERSONAL"`, `"VENTURE"` | Цель кредита |
| `loan_grade` | `str` (`Literal`) | да | `"A"`, `"B"`, `"C"`, `"D"`, `"E"`, `"F"`, `"G"` | Кредитный грейд |
| `loan_amnt` | `float` | да | `> 0`, `<= 35 000` | Запрашиваемая сумма кредита |
| `cb_person_default_on_file` | `str` (`Literal`) | да | `"Y"`, `"N"` | Наличие дефолта в кредитной истории |
| `cb_person_cred_hist_length` | `int` | да | `2..30` | Длина кредитной истории, лет |

### Выходные поля `POST /predict`

```json
{
  "probability_of_default": 0.028228600383371338,
  "decision": "approve",
  "threshold": 0.16
}
```

- `probability_of_default` (`float`, `0..1`) — предсказываемая моделью вероятность дефолта.
- `decision` (`"approve" | "decline"`) — решение по заявке: `"decline"` при `probability_of_default >= threshold`, иначе `"approve"`.
- `threshold` (`float`, `0..1`) — применённый порог отсечения (по умолчанию `0.16` из `models/metadata.json`, может быть переопределён через переменную окружения `THRESHOLD`).

### Коды ответов

- `200 OK` — запрос успешно обработан.
- `422 Unprocessable Entity` — ошибка валидации входных данных (отсутствует обязательное поле, значение вне допустимого диапазона, неизвестная категория, нарушено условие `person_emp_length <= person_age - 14` или передано лишнее поле).
- `503 Service Unavailable` — файл модели не найден или не загружен при старте сервиса (`model_loaded = false`).

## Модель

Основная модель: **`CatBoostClassifier`**. Линейный бейзлайн: **`LogisticRegression`** ([02_baseline.ipynb](file:///Users/mac/Documents/Portfolio/credit-scoring/notebooks/02_baseline.ipynb)). Все этапы выбора признаков, гиперпараметров, проверки калибровки и подбора порога выполнены на обучающей выборке `train` (`25 918` строк) по 5-фолдовой стратифицированной кросс-валидации ([03_main_model.ipynb](file:///Users/mac/Documents/Portfolio/credit-scoring/notebooks/03_main_model.ipynb)).

### Ключевые решения

- **Исключение `loan_int_rate` и сохранение `loan_grade`:** в присутствии `loan_grade` ставка `loan_int_rate` не даёт значимого прироста качества на кросс-валидации (`+0.0005` `ROC-AUC`), содержит около `10%` пропусков (`3 116` до очистки / `3 091` после очистки) и усложняет контракт API. `loan_grade` сохранён как основной индикатор кредитного риска, а модель без обоих банковских признаков оценена отдельно для проверки устойчивости ([03_main_model.ipynb](file:///Users/mac/Documents/Portfolio/credit-scoring/notebooks/03_main_model.ipynb), шаги 1 и 2).
- **Нативная обработка признаков и расчёт `loan_percent_income`:** `CatBoost` получает категориальные признаки и пропуски в `person_emp_length` (`NaN`) напрямую без ручной импутации медианой и one-hot кодирования. Признак `loan_percent_income` пересчитывается в `src/features.py` по формуле `loan_amnt / person_income`; на кросс-валидации подтверждено отсутствие потери качества ([03_main_model.ipynb](file:///Users/mac/Documents/Portfolio/credit-scoring/notebooks/03_main_model.ipynb), шаг 2).
- **Отказ от дополнительных признаков (feature engineering):** проверены 5 кандидатов (`income_per_age`, `cred_hist_to_age`, `emp_to_age`, `loan_to_emp_income`, `age_at_first_credit`) по отдельности и совместно. Ни один вариант не дал прироста `ROC-AUC` выше шума по фолдам (максимум `+0.0002` при `std` около `0.003`), поэтому оставлен базовый набор из 10 признаков ([03_main_model.ipynb](file:///Users/mac/Documents/Portfolio/credit-scoring/notebooks/03_main_model.ipynb), шаг 3).
- **Подбор гиперпараметров (`Optuna`):** поиск на 50 итераций (`5-fold CV` с early stopping) значимого прироста качества не дал — на отложенной выборке `test` метрики `tuned` и `default` практически идентичны (`ROC-AUC` `0.9486` против `0.9483`), однако финальная модель стала компактнее: глубина дерева `depth = 4` (вместо `6`) и `662` итерации (вместо `1 000`) ([03_main_model.ipynb](file:///Users/mac/Documents/Portfolio/credit-scoring/notebooks/03_main_model.ipynb), шаги 4 и 6).
- **Калибровка вероятностей:** дополнительная калибровка не потребовалась. На out-of-fold предсказаниях `train` сырые вероятности `CatBoost` (`raw`: `Brier = 0.05253`, `log loss = 0.18871`) не уступают `isotonic` (`Brier = 0.05256`, `log loss = 0.19095`) и превосходят `sigmoid` (`Brier = 0.05415`, `log loss = 0.19959`) ([03_main_model.ipynb](file:///Users/mac/Documents/Portfolio/credit-scoring/notebooks/03_main_model.ipynb), шаг 5).
- **Выбор порога отсечения (`0.16`):** порог выбран на OOF-предсказаниях `train` из условия минимизации средней цены ошибки при допущении, что пропуск дефолта (`FN`) в `c = 5` раз дороже ложного отказа платёжеспособному клиенту (`FP = 1`). Для альтернативных сценариев `c = 3` и `c = 10` оптимальные пороги составляют `0.24` и `0.08`; во всех трёх случаях эмпирический оптимум совпал с теоретическим порогом Байеса `1 / (1 + c)` с точностью до шага сетки `0.01` ([03_main_model.ipynb](file:///Users/mac/Documents/Portfolio/credit-scoring/notebooks/03_main_model.ipynb), шаг 5).

### Операционные метрики при пороге `0.16` на `test`

Матрица ошибок на `6 480` заявках тестовой выборки: `TN = 4 599`, `FP = 463`, `FN = 201`, `TP = 1 217`.

- **Доля одобрений (`approval rate`):** `74,07%` (`0.7407`).
- **Полнота обнаружения дефолтов (`recall`):** `85,83%` (`0.8583`).
- **Точность отказов (`precision`):** `72,44%` (`0.7244`).
- **Доля дефолтов среди одобренных заявок (`bad rate`):** `4,19%` (`0.0419`) против `21,88%` во всей тестовой выборке.
- **Средняя цена ошибки на заявку (при `c = 5`):** `0.2265` при пороге `0.16` против `0.2804` при стандартном пороге `0.50` (снижение средних потерь на `0.0539`, или на `19,2%`).

### Интерпретация (`SHAP`)

Анализ значений `SHAP` на тестовой выборке ([03_main_model.ipynb](file:///Users/mac/Documents/Portfolio/credit-scoring/notebooks/03_main_model.ipynb), шаг 7) показывает следующий характер использования признаков моделью:
- Наибольший вклад в разделение заёмщиков вносят отношение суммы кредита к доходу (`loan_percent_income`), статус владения жильём (`person_home_ownership`), кредитный грейд (`loan_grade`), годовой доход (`person_income`) и цель кредита (`loan_intent`).
- Прогнозируемый риск дефолта резко возрастает при доле кредита от дохода выше `25–30%`, при аренде жилья (`RENT`) и при грейдах `D`–`G`.
- Прогнозируемый риск снижается при высоком годовом доходе и наличии собственного жилья (`OWN`).
- Значения `SHAP` (в единицах `log-odds`) отражают вклад признаков в прогноз конкретной модели, но не доказывают причинно-следственную связь в данных.

## Воспроизведение обучения и тестирование

### Переобучение модели

1. Скачать датасет [Credit Risk Dataset](https://www.kaggle.com/datasets/laotse/credit-risk-dataset) с Kaggle и поместить CSV-файл по пути, который ожидает `src/data.py`:

```text
data/raw/credit_risk_dataset.csv
```

2. Создать виртуальное окружение Python 3.12 и установить зависимости для разработки и обучения:

```bash
python3.12 -m venv .venv
source .venv/bin/activate
pip install -r requirements-dev.txt
```

3. Запустить скрипт обучения:

```bash
python -m src.train
```

Скрипт выполняет загрузку и очистку данных (`src/data.py`), расчёт признаков (`src/features.py`), обучение `CatBoostClassifier` с зафиксированными гиперпараметрами, расчёт метрик на отложенной выборке (`src/evaluate.py`) и перезаписывает артефакты:
- `models/model.pkl` — сериализованная модель `CatBoostClassifier`;
- `models/metadata.json` — параметры модели, список признаков, порог `0.16`, метрики на `test` и версии библиотек.

При необходимости сохранить очищенный датасет в `data/processed/credit_risk_clean.csv` отдельно выполняется команда `python -m src.data`.

### Запуск тестов

```bash
pytest
```

Набор включает быстрые модульные тесты подготовки признаков и одиночного предсказания модели (`tests/test_model.py`), а также интеграционные тесты эндпоинтов `/health` и `/predict`, граничных условий валидации, переопределения порога и кода `503` при отсутствии модели (`tests/test_api.py`).

### Исследовательские ноутбуки

Ноутбуки расположены в каталоге `notebooks/` и предназначены для последовательного чтения:
1. [notebooks/01_eda.ipynb](file:///Users/mac/Documents/Portfolio/credit-scoring/notebooks/01_eda.ipynb) — разведочный анализ данных, выявление аномалий, анализ пропусков, дубликатов и распределений признаков.
2. [notebooks/02_baseline.ipynb](file:///Users/mac/Documents/Portfolio/credit-scoring/notebooks/02_baseline.ipynb) — построение линейного бейзлайна (`LogisticRegression`), проверка влияния `loan_grade`, `loan_int_rate` и коллинеарности признаков.
3. [notebooks/03_main_model.ipynb](file:///Users/mac/Documents/Portfolio/credit-scoring/notebooks/03_main_model.ipynb) — переход к `CatBoost`, отбор признаков, эксперименты с feature engineering, тюнинг `Optuna`, проверка калибровки, выбор порога по матрице цен ошибок, финальная оценка на `test` и `SHAP`-интерпретация.

## Ограничения

Проект носит учебный характер и не предназначен для использования в реальном кредитном конвейере:
- **Отсутствие временной разметки:** в датасете нет дат подачи заявок и выдачи кредитов, поэтому невозможна проверка устойчивости модели во времени (`out-of-time` валидация).
- **Смещение выборки (`reject inference`):** целевая переменная известна только по исторически одобренным и выданным кредитам; платёжное поведение отклонённых заёмщиков в данных не отражено.
- **Условная модель стоимости ошибок:** отношение цен ошибок `c = 5` фиксировано как портфельное допущение; в реальном кредитовании потери зависят от суммы конкретного договора, процентной маржи, срока и доли возврата при взыскании (`LGD`).
- **Зависимость от банковского грейда и регуляторные ограничения:** модель существенно опирается на внутренний грейд `loan_grade` (при удалении `loan_grade` и `loan_int_rate` `ROC-AUC` на `test` снижается с `0.9486` до `0.9113`), а прямое использование возраста (`person_age`) и ряда анкетных признаков в кредитных организациях ограничивается отраслевым регулированием.
- **Отсутствие MLOps-контура:** в проекте нет мониторинга дрейфа входных данных (`PSI`) и предсказаний, автоматического переобучения по расписанию, CI/CD-пайплайна и независимой модельной валидации.
- **Инфраструктурные ограничения API:** сервис не включает аутентификацию и авторизацию клиентов, ограничение частоты запросов (`rate limiting`), базу данных и аудит-лог принятых кредитных решений.

Для перевода подобного решения в промышленную эксплуатацию потребовались бы валидация на `out-of-time` выборке, калибровка экономики порога на реальных данных `LGD`/`EAD`, внедрение аутентификации и журналирования решений в хранилище данных, настройка мониторинга стабильности признаков (`PSI`) и регламента периодического переобучения модели.
