# Credit Scoring

![CI](https://github.com/rmarufs/credit-scoring/actions/workflows/ci.yml/badge.svg?branch=main)

Модель, которая оценивает вероятность того, что заёмщик не вернёт кредит, и сервис, который отдаёт эту оценку по HTTP. Внутри CatBoost, REST API на FastAPI, Docker и тесты.

**Попробовать вживую:** [credit-scoring-su6y.onrender.com](https://credit-scoring-su6y.onrender.com/) откроет Swagger, где можно отправить тестовую заявку одним нажатием. Сервер бесплатный и засыпает без нагрузки, поэтому первый запрос может занять около минуты. Реальные персональные данные вводить не нужно.

## Что здесь интересного

- **Порог одобрения выбран не по умолчанию, а по цене ошибок.** Пропущенный дефолт дороже, чем отказ хорошему клиенту, поэтому порог 0.16 вместо привычных 0.5. При допущении, что дефолт дороже отказа в 5 раз, это снижает среднюю цену ошибок примерно на 19%.
- **Модель проверена на зависимость от банковского грейда.** Кредитный грейд назначает сам банк, и он уже содержит оценку риска. Без грейда и процентной ставки модель всё равно даёт ROC-AUC 0.911 против 0.876 у логистической регрессии с полным набором признаков.
- **Подбор гиперпараметров не помог, и это написано прямо.** Optuna на отложенной выборке не дала значимого прироста. Остался компактный вариант (глубина 4, 662 итерации), потому что он проще, а не потому что лучше.
- **Одна и та же подготовка признаков в обучении и в API.** Это исключает ситуацию, когда модель в проде видит данные иначе, чем на обучении.

## Результаты

Отложенная выборка (6 480 заявок), использована один раз после того, как все решения были приняты:

| Модель | ROC-AUC | PR-AUC | KS | Gini |
|---|---|---|---|---|
| Логистическая регрессия (baseline) | 0.876 | 0.710 | 0.603 | 0.753 |
| CatBoost без тюнинга | 0.948 | 0.912 | 0.781 | 0.897 |
| **CatBoost (финальная)** | **0.949** | **0.912** | **0.779** | **0.897** |
| CatBoost без грейда и ставки | 0.911 | 0.832 | 0.661 | 0.823 |

95% доверительный интервал ROC-AUC финальной модели: 0.941–0.956.

При пороге 0.16 одобряется около 74% заявок, ловится около 86% будущих дефолтов, а среди одобренных дефолтят 4,2% (во всей выборке 21,9%).

Что модель считает рискованным (по SHAP): кредит выше примерно 25–30% годового дохода, аренда жилья, кредитные грейды D–G. Риск ниже при высоком доходе и собственном жилье. Это описание того, как модель использует признаки, а не доказательство причин.

## Как принимались решения

Все эксперименты и обоснования лежат в ноутбуках, здесь только суть:

- **Ставка `loan_int_rate` убрана, грейд оставлен.** При живом грейде ставка не добавляет качества, в ней около 10% пропусков, и она усложняет API.
- **CatBoost получает пропуски и категории как есть**, без заполнения медианой и one-hot. Качество не страдает, а код проще. Долю кредита от дохода сервис считает сам.
- **Новые признаки (отношения возраста, стажа, кредитной истории) не помогли.** Проверено пять вариантов, ни один не дал прироста выше шума кросс-валидации.
- **Калибровка вероятностей не понадобилась:** сырые вероятности CatBoost откалиброваны не хуже, чем после isotonic и sigmoid.

## Быстрый старт

Обученная модель лежит в репозитории, датасет для запуска API не нужен. Нужен только Docker.

```bash
git clone https://github.com/rmarufs/credit-scoring
cd credit-scoring
docker compose up --build
```

Swagger откроется на `http://localhost:8000/docs`. Пример запроса:

```bash
curl -X POST http://localhost:8000/predict \
  -H "Content-Type: application/json" \
  -d '{
    "person_age": 28,
    "person_income": 65000,
    "person_home_ownership": "MORTGAGE",
    "person_emp_length": 5,
    "loan_intent": "EDUCATION",
    "loan_grade": "B",
    "loan_amnt": 8000,
    "cb_person_default_on_file": "N",
    "cb_person_cred_hist_length": 6
  }'
```

Ответ:

```json
{"probability_of_default": 0.028, "decision": "approve", "threshold": 0.16}
```

Решение `decline` выдаётся, если вероятность не меньше порога. Порог по умолчанию берётся из `models/metadata.json` и переопределяется переменной окружения `THRESHOLD`.

**Эндпоинты:** `GET /health` (состояние сервиса и версия CatBoost) и `POST /predict` (оценка заявки). Все допустимые значения полей описаны в Swagger. Неверные данные API отклоняет с кодом 422, например стаж больше, чем `возраст − 14`.

## Данные

[Credit Risk Dataset](https://www.kaggle.com/datasets/laotse/credit-risk-dataset) с Kaggle: 32 581 заявка, цель `loan_status` (1 означает дефолт, доля 21,8%). Из данных удалены 18 строк с невозможными значениями (возраст до 144 лет, стаж 123 года) и 165 дубликатов, осталось 32 398 строк. Пропуски в стаже оказались информативными: среди заёмщиков без указанного стажа дефолтят чаще (31,5% против 21,6%), поэтому их не удаляли. Сырой файл в репозиторий не входит.

## Ограничения

Это учебный проект, не готовый к реальному кредитованию:

- в датасете нет дат, поэтому устойчивость модели во времени не проверена;
- исходы известны только по выданным кредитам, судьба отказанных заёмщиков неизвестна;
- цена ошибки (дефолт дороже отказа в 5 раз) принята как допущение, в банке она зависит от суммы кредита и маржи;
- модель заметно опирается на банковский грейд, а использование возраста и других личных признаков в реальных банках регулируется;
- нет мониторинга качества и дрейфа данных, переобучения по расписанию, автоматического развёртывания, аутентификации и независимой валидации модели.

Для продакшена понадобились бы реальные данные с временной осью, расчёт цены ошибки по настоящим потерям банка, мониторинг и регламент переобучения.
