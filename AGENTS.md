# AGENTS.md

Проект: кредитный скоринг. Модель оценивает вероятность дефолта заёмщика, API отдаёт предсказания, всё упаковано в Docker.

## Стек
- Python 3.11
- FastAPI, Uvicorn, Pydantic v2
- scikit-learn (Pipeline), XGBoost или LightGBM (уточнить после baseline)
- pandas, numpy, joblib
- pytest, httpx (тесты API)
- Docker, docker compose
- Базы данных нет

Точные версии берём из `requirements.txt`, не меняем их без причины.

## Структура
- `src/` обучение: загрузка и очистка данных, признаки, train, evaluate
- `app/` API: только загрузка готовой модели и предсказания
- `models/` артефакты: `model.joblib`, `model_meta.json`
- `data/` данные, в git не попадают
- `notebooks/` EDA и baseline
- `docs/` документация проекта

## Правила для агента
1. Читай только те документы из `docs/`, которые названы в задаче. Остальные не открывай.
2. Работай только в рамках задачи. Файлы и папки, которые в ней не упомянуты, не трогай.
3. API ничего не обучает: он только загружает `models/model.joblib` при старте. Обучение живёт в `src/`.
4. В Docker-образ попадают только `app/`, `models/` и `requirements.txt`. Ноутбуки и сырые данные не копируем.
5. Конфигурация через переменные окружения, пример в `.env.example`. Секретов в коде нет.
6. Не создавай тестовые и временные файлы при отладке. Тесты пишем только в `tests/` и только если это входит в задачу.
7. Не добавляй зависимости без необходимости, а если добавил, упомяни об этом в ответе.
8. Код простой и читаемый, с типами и короткими докстрингами. Без лишних абстракций.
9. Важные решения по данным и модели не принимай сам, а предлагай. Их записывает человек в `docs/DECISIONS.md`.

## Документы
- `docs/SPEC.md` контракт API: эндпоинты, поля, ошибки
- `docs/ARCHITECTURE.md` устройство проекта и что попадает в образ
- `docs/DATA.md` описание датасета
- `docs/DECISIONS.md` журнал решений
