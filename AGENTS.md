# AGENTS.md

Проект: кредитный скоринг. Модель оценивает вероятность дефолта заёмщика, API отдаёт предсказания, всё упаковано в Docker.

## Стек
- Python 3.12
- FastAPI, Uvicorn, Pydantic v2
- scikit-learn (Pipeline)
- Catboost
- pandas, numpy, joblib
- pytest, httpx (тесты API)
- Docker, docker compose
- Базы данных нет

Точные версии берём из `requirements.txt`, не меняем их без причины.

## Структура
- `src/` обучение: загрузка и очистка данных, признаки, train, evaluate
- `app/` API: только загрузка готовой модели и предсказания
- `models/` артефакты: `model.pkl`, `metadata.json`
- `data/` данные, в git не попадают
- `notebooks/` EDA и baseline
- `docs/` документация проекта

## Правила для агента
1. Читай только те документы из `docs/`, которые названы в задаче. Остальные не открывай.
2. Работай только в рамках задачи. Файлы и папки, которые в ней не упомянуты, не трогай.
3. API ничего не обучает: он только загружает готовую модель при старте. Кастомная логика признаков живёт в `src/features.py`, модель обучается и сохраняется из `src/train.py` (не из ноутбука).
4. В Docker-образ попадают только `app/`, `src/`, `models/` и `requirements.txt`. Ноутбуки и сырые данные не копируем.
5. Конфигурация через переменные окружения, пример в `.env.example`. Секретов в коде нет.
6. Не создавай тестовые и временные файлы при отладке. Тесты пишем только в `tests/` и только если это входит в задачу.
7. Не добавляй зависимости без необходимости, а если добавил, упомяни об этом в ответе.
8. Код простой и читаемый, с типами и короткими докстрингами. Без лишних абстракций.

## Правила оформления ноутбука

1. Одна ячейка = одно действие. Обучение, подсчёт метрик, таблица с цифрами и график живут в разных ячейках. Функции определяем в отдельной ячейке, вызываем в другой.
2. Выводы пишем в markdown-ячейке, только там, где есть что сказать: решение, неожиданный результат, причина выбора. Не пересказывай цифры, которые уже видны в выводе ячейки. Вывод короткий (2-5 строк) и отвечает на вопрос «что из этого следует и что решили». Если сказать нечего, ячейку с выводом не делай.
3. Короткий markdown-заголовок перед каждым блоком: что делаем и зачем, одной-двумя фразами.
4. Код без лишних комментариев и без print-ов, дублирующих очевидное. Названия переменных понятные.
5. Весь ноутбук должен проходить сверху вниз без ошибок (Restart & Run All).
